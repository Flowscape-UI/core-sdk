# Code of Conduct

Flowscape is an open-source project intended to support productive technical collaboration. Everyone participating in the project is expected to communicate professionally and treat others with respect.

## Expected Behavior

Participants should:

- discuss ideas, code, and technical decisions without attacking people;
- provide constructive, specific feedback;
- assume good intent while still addressing problems clearly;
- respect different levels of experience, backgrounds, and communication styles;
- keep discussions relevant to the project and the issue being discussed;
- accept reasonable maintainer decisions after concerns have been heard;
- help keep issues, pull requests, discussions, and other project spaces useful to everyone.

Technical disagreement is welcome. Personal hostility is not.

## Unacceptable Behavior

The following behavior is not acceptable in project spaces:

- harassment, threats, intimidation, or targeted abuse;
- discriminatory or demeaning comments;
- personal insults or sustained hostile communication;
- sexualized language, imagery, or unwanted sexual attention;
- deliberately publishing another person's private information;
- spam, repeated disruption, or intentionally derailing discussions;
- impersonation or deceptive behavior intended to harm another participant;
- retaliation against someone who reports a conduct concern;
- other behavior that maintainers reasonably determine is harmful to the project community.

## Technical Discussions

Flowscape welcomes strong technical opinions and architectural debate.

When disagreeing:

- focus on observable behavior, trade-offs, constraints, and evidence;
- explain why a proposal may create problems rather than dismissing the person proposing it;
- prefer reproducible examples, benchmarks, tests, and concrete alternatives;
- avoid turning code review into a contest over status or authority.

Maintainers may close discussions that become repetitive, hostile, unrelated, or no longer productive.

## Maintainer Responsibilities

Project maintainers are responsible for interpreting and enforcing this Code of Conduct in project-controlled spaces.

Depending on the severity and history of an incident, maintainers may:

1. provide a private or public warning;
2. remove or edit inappropriate content where the platform allows it;
3. lock or close a discussion, issue, or pull request;
4. temporarily restrict participation;
5. permanently block a participant from project spaces.

Actions should be proportionate to the behavior and focused on protecting a productive project environment.

## Reporting a Problem

Conduct concerns should be reported to the project maintainers.

For sensitive matters, do **not** include private or harmful details in a public issue. Ask the maintainers for a private contact method without disclosing the incident publicly.

Reports should include, when possible:

- where the incident occurred;
- what happened;
- relevant links or screenshots;
- any important context;
- whether immediate action may be required.

Maintainers should handle reports discreetly and share information only as needed to evaluate and address the situation.

## Scope

This Code of Conduct applies to project-controlled spaces, including:

- GitHub issues and pull requests;
- GitHub Discussions;
- code review;
- documentation and project-managed community spaces;
- other spaces where someone is clearly representing Flowscape in an official capacity.

## Good-Faith Participation

This policy is intended to protect collaboration, not suppress ordinary disagreement or reasonable criticism.

Good-faith technical criticism, bug reports, security research, architectural disagreement, and respectful negative feedback are allowed and encouraged.

By participating in Flowscape project spaces, contributors agree to follow this Code of Conduct.
